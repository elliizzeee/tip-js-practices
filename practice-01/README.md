## Задание 2. Исследование типов и преобразований

Файл `js/types.js` запущен в Node.js и в браузере. Результаты совпали.

| № | Выражение | Ожидание до запуска | Значение | Тип результата | Объяснение |
|:-:|---|---|---|---|---|
| 1 | `"8" + 2` | `"82"` (строка) | `"82"` | string | Оператор `+` при наличии строки склеивает числа |
| 2 | `"8" - 2` | `6` (число) | `6` | number | Оператор `-` приводит строку к числу, так как работает только с числами |
| 3 | `Number("8") + 2` | `10` (число) | `10` | number | Преобразование строки в число + сложение |
| 4 | `"12" > "3"` | `true` (12 > 3) | `false` | boolean | Строки сравниваются по порядку: `"1" < "3"` |
| 5 | `12 === "12"` | `false` | `false` | boolean | Строгое сравнение без приведения типов |
| 6 | `Number("")` | `0` | `0` | number | Пустая строка преобразуется в 0 |
| 7 | `Number("text")` | `NaN` | `NaN` | number | Нечисловая строка → `NaN` (тип всё равно number) |
| 8 | `Boolean("false")` | `false` | `true` | boolean | Любая непустая строка → `true` |
| 9 | `typeof null` | `"null"` | `"object"` | string | Историческая особенность JavaScript |
| 10 | `typeof NaN` | `"NaN"` | `"number"` | string | `NaN` имеет тип number |

### Подробные объяснения

1. **Объединение строки с числом (`"8" + 2` → `"82"`)**
   Оператор `+` в JavaScript: если хотя бы один из операндов строка, то второй тоже превращается в строку и происходит склеивание. Поэтому `"8" + 2` даёт не `10`, а строку `"82"`.

2. **Преобразование пустой строки `Number("")` в `0`**
   `Number()` превращает пустую строку в `0`. Это историческое решение JavaScript: нет данных — следовательно, ноль.

3. **Значение `NaN` (Not a Number)**
   `NaN` — специальное числовое значение, которое означает, что результат операции не получился. Например, `Number("text")` возвращает `NaN`. `typeof NaN` = `"number"`, потому что это значение относится к числовому типу, хоть и означает «не число».

4. **Логическое преобразование непустой строки (`Boolean("false")` → `true`)**
   `Boolean()` возвращает `false` только для пустой строки `""`, числа `0`, `null`, `undefined` и `NaN`. Любая непустая строка — это `true`, даже если она содержит слово `false`. Важна длина строки: если есть символы — `true`, нет символов — `false`.

## Задание 6. Почему проверки `< 0` недостаточно

Одной проверки `< 0` недостаточно, потому что мусорный ввод `Number()` превращает в `0`, `NaN` или `Infinity`. Ни одно из этих значений не является отрицательным. Значит, проверка `< 0` их пропустит, и программа выдаст бессмысленный результат. Поэтому проверка должна выполняться последовательно: сначала тип данных, затем конечность (`Number.isFinite`), затем целочисленность (`Number.isInteger`), и только потом границы.
