## 4. Модель данных и функции

Распределение файлов: data.js - исходные наборы; task-service.js - девять чистых функций без вывода; main.js - сценарий и печать; checks.js - проверки

Операции изменения (addTask, setTaskCompleted, renameTask, removeTask) возвращают { ok: true, tasks: <новый массив> } или { ok: false, error: "..." }. Операции чтения (findTaskById, getPendingTasks, getTaskTitles, getTaskStats) возвращают объект, массив или undefined без обёртки

| Поле | Правило | 
|---|---|
id |	положительное безопасное целое (Number.isSafeInteger(id) && id > 0)
title |	строка, после trim() длина 1–100
completed |	boolean; при создании всегда false
priority |	"low" | "medium" | "high"; по умолчанию "medium"


**Почему id не равен индексу:** индекс - это текущая позиция в массиве, она меняется при удалении соседних элементов. id - постоянный идентификатор записи, он присваивается один раз и не меняется

**Почему getTaskStats возвращает число, а не строку с процентом:** расчёт и отображение разделены. Функция возвращает числовой progress, а форматирование выполняется только в main.js при выводе. Это позволяет использовать getTaskStats в любом контексте, не привязываясь к формату вывода


**Какие объекты копируются при изменении задачи:** создаётся новый массив ([...tasks] или tasks.map/filter), и новый объект только изменённой записи ({ ...task, ... }). Остальные объекты переиспользуются - они не мутируются, поэтому ссылки допустимо сохранять

## 9. Вывод

По сравнению с ПР1, где операции выполнялись над отдельными переменными, здесь каждая задача представлена объектом, а список — массивом. Логика выделена в девять функций модуля task-service.js, которые возвращают значения ({ ok, task }, { ok, tasks }, массивы, объекты сводки), а не печатают их — вывод вынесен в main.js. Отсутствие мутации проверено сравнением исходных объектов с эталоном после каждой операции: изменённая запись пересоздаётся через spread, остальные переиспользуются, а новые массивы создаются через map, filter, [...tasks]. Исправленная ошибка — пропущенный return в стрелочной функции эксперимента 2, из-за которого square(4) возвращал undefined вместо 16
